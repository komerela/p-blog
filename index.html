The Shift

Building has never been easier — or more nuanced

I marvel at how easy it has become to spin up a project today. But ease is deceptive. The real question isn’t whether you can ship something — it’s whether what you ship will hold up: at scale, on a patchy network, behind a locked-down firewall, or under a production security audit.

The difference between a weekend prototype and a deployable product comes down to architecture decisions made before a single line of application code is written. That’s the layer Perplexity Computer has fundamentally changed for me — and I want to show you exactly how.

The Stack

Architecture first, idea second

Before I write a single line of feature code, I define the entire infrastructure. This is a discipline that took time to learn: the how of deployment, security, and observability needs to be decided before the what of product features.

Transactions vs. posts: a database decision that matters

Losing a social media post is an inconvenience. Losing a financial transaction or a health record could be a life-or-death event. When data has permanence stakes, PostgreSQL earns its place. When it’s high-velocity, schema-flexible data — activity logs, social feeds, media metadata — MongoDB makes the trade-off correctly.

The Method

The skill file system: my best practices, codified

Instead of re-explaining my architecture to an AI agent on every new project, I designed a set of reusable skill files — one for frontend, one for deployment, one for database patterns, one for monitoring. Each file encodes my best practices, not someone else’s boilerplate.

The critical insight: don’t inherit other people’s bugs. Most shared templates carry silent assumptions, outdated patterns, and debt you didn’t incur. Start from an analysis of your own past projects. Your skills are derived from your own battle-tested patterns — and @PerplexityAI’s Perplexity Computer makes generating them from that analysis easier than ever.

Step by Step

How I build a new project end-to-end

From the moment I have an idea to the moment autonomous agents are generating production code against my specifications, this is the exact workflow I run.

1

Write the idea and data flow

I describe what the app does and how data moves from source to output — every entity, relationship, and state change. For a March Madness predictor: team rosters, historical performance, player scoring, model output format.

2

Break it into tasks with Perplexity

I paste the full description and ask Perplexity to decompose the project into manageable, independently-shippable tasks. I get a clear backlog before a single line of code is written.

3

Create the GitHub repo with scaffolding

I initialize the repo, commit a stack-tuned README and .gitignore, then connect Perplexity Computer. This gives the agent full context from day one.

4

Copy skills from the infrastructure repo

I reference my shared GitHub skills repo and copy the relevant files into the new project. The agent has my frontend, backend, deployment, security, and monitoring best practices available as context — not from the internet, but from my own work.

5

Generate idea-specific skills with Perplexity Computer

I ask Perplexity Computer to build any skill files the project needs that aren’t in the base set. I also enforce a line-of-code limit per file to keep things maintainable and prevent monstrous code files.

6

Let autonomous agents build and iterate

With skills loaded, I instruct Perplexity Computer’s specialized agents — including Claude — to build the application. Agents understand my specs, follow my patterns, test output, and continuously improve. The skill files act as a contract they never break.

The real unlock: Once you have a skills library, you’re not rebuilding your architecture every time. You’re composing. Each new project starts with a proven foundation and extends it with only the domain-specific logic that’s actually new. The agents understand your constraints — file size limits, preferred patterns, deployment targets — because you’ve already written them down.

Deployment Reality

Building for where your users actually are

Scalability and security aren’t the only dimensions that matter at deployment time. If your users are in places like Moreno Valley, California, network conditions and fire-related disruptions are a design constraint just as real as your schema or your auth flow. Tailscale keeps the server private. Cloudflare proxies and caches at the edge. Docker ensures the same runtime everywhere. And monitoring tells you when performance degrades in the field — not after a user complaint.

The skill files encode all of this. When Perplexity Computer generates new project code using my deployment skill, these considerations are baked in by default — not bolted on later.
